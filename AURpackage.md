Крок 1: Створення тегу (Tag) на GitHub

Твій пакет в AUR не повинен тягнути код із нестабільної гілки main. Він завантажує зафіксований архів (наприклад, v0.2.0.tar.gz).

    Відкрий термінал у своїй головній папці з кодом проєкту EternalTerminal.

    Створи новий тег для поточної версії (припустимо, це 0.2.0): "git tag v0.2.0"

    Відправ цей тег на сервер: "git push origin v0.2.0"

    Зайди на сторінку свого репозиторію на GitHub, відкрий розділ Releases і натисни "Draft a new release". Обери свій новий тег v0.2.0 і опублікуй реліз. GitHub автоматично згенерує архів із вихідним кодом.


Крок 2: Підготовка локальної папки AUR

Тепер переходимо в ту саму окрему папку test-eternal-terminal, яку ти використовуєш для роботи з AUR. Саме там лежить файл PKGBUILD — головна інструкція для системи makepkg.

    1: Оновлюємо версію в PKGBUILD. Відкрий файл PKGBUILD у папці test-eternal-terminal. Нам треба змінити дві змінні на самому початку файлу:Оновити pkgver на нову версію.  Скинути pkgrel (реліз пакета) назад до 1, оскільки це перша збірка нової версії.  Зміни ці рядки:
    ```console
    pkgname=eternal-terminal
    pkgver=0.2.0  # <-- НОВА ВЕРСІЯ
    pkgrel=1      # <-- СКИДАЄМО ДО 1
    ```

    2: Оновлюємо контрольну суму (sha256sums) Оскільки вихідний код змінився, стара контрольна сума 8e8bbb19b44285bc1a256e8450381ed68246a1a14146aab9e477fc6d8d258352 більше не підходить. Якщо ми спробуємо зібрати пакет зараз, система безпеки Arch Linux видасть помилку.
    Тобі не потрібно рахувати її вручну. Відкрий термінал у папці test-eternal-terminal і просто виконай цю команду:  
    ```console
    updpkgsums
    ```
    Що відбудеться: Ця утиліта автоматично прочитає твоє посилання source, завантажить новий архів v0.2.0.tar.gz з GitHub, вирахує його хеш і сама акуратно перезапише масив sha256sums у твоєму PKGBUILD

    3: Локальна збірка та тестування. Тепер ми перевіримо, чи збирається наш новий пакет і чи працює він у системі. У цій же папці виконай:
    ```console
    rm -rf src/ pkg/ # <-- ОЧИСТИТИ КЕШ
    makepkg -si
    ```
    Прапорець -s (sync) автоматично перевірить залежності (qt6-base, qt6-declarative).  Прапорець -i (install) запропонує встановити пакет у систему (через pacman) відразу після успішної збірки. Після встановлення напиши в терміналі eternal-terminal (або знайди його в меню програм) і перевір, чи запускається нова версія з усіма нашими фічами (теми, скрол, виділення).

    4: Оновлюємо метадані AUR (.SRCINFO)
    AUR не читає сам PKGBUILD для відображення інформації на сайті, він читає спеціальний файл .SRCINFO. Його потрібно обов'язково оновити перед пушем.
    Виконай:
    ```console
    makepkg --printsrcinfo > .SRCINFO
    ```

    5: Відправляємо оновлення в AUR
    Якщо термінал запустився і працює чудово, залишилося лише зафіксувати зміни в Git і відправити їх на сервери AUR:

   ```console
    git add PKGBUILD .SRCINFO
    git commit -m "Update to version 0.2.0"
    git push
   ```

Усе! Після цього користувачі AUR побачать нову версію 0.2.0-1 і зможуть оновитися через свій yay
```console
yay -S eternal-terminal
```
